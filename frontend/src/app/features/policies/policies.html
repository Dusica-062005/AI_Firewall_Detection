How precedence works

@if (policyVersion()) { Active set {{ policyVersion() }} }
  1. Most restrictive wins. BLOCK, then LOCAL_ONLY, then REDACT, then ALLOW. A broad allow never overrides a restriction.
  2. Priority breaks ties only. Among rules with the same action, the lower number is reported as decisive.
  3. Destinations narrow. The request uses the most restrictive destination of every matching rule: NONE, LOCAL, CLOUD.
  4. Deny by default. Uncovered entities are kept local; no applicable policy or any failure blocks cloud transmission.
